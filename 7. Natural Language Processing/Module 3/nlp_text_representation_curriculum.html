What is Feature Extraction from Text?

🎯 Goal: Understand what "feature extraction from text" means in simple words
💡 Concept

Imagine you want a computer to decide whether a movie review is positive or negative.


The review is in English. But the computer does not understand English.


The computer only understands numbers.


So we have to convert the text into numbers. This process is called:


Feature Extraction from Text Text Representation Text Vectorization

All three mean the same thing — converting text into numbers (vectors).

🧠 Mental Model
Think of it like this:

You want to teach a blind robot to understand books. But the robot can only feel numbers. So you convert every word into a number, so the robot can "read."

This is exactly what feature extraction does — it gives the ML model a "numeric version" of your text.
🖼️ Visual
Input Text: "The movie was great!" ↓ Feature Extraction (our job today) ↓ Numbers: [0, 1, 0, 0, 1, 0, 1, 0, 0, 0, ...] ↓ ML Algorithm reads numbers → Predicts: "Positive" ✅
🔄
Text → Numbers → Prediction

The ML model never sees the words directly. It only sees the numbers we create from those words.

🧠 Think Questions
❓ If ML models only understand numbers, how do you think Google Translate works?
❓ Can two different sentences have the same numbers? What problems could that cause?

🌍 Real-Life Example
🛒 Example: Village Shopkeeper

A shopkeeper records sales as "good day," "bad day," "okay day." But the accountant can only work with numbers. So someone converts: "good" → 3, "okay" → 2, "bad" → 1. This conversion is feature extraction!

Why Do We Need Feature Extraction?

🎯 Goal: Understand why good features are the most important part of ML
💡 Core Reason

In any Machine Learning problem, you need to give the algorithm input features — the things that help it make a prediction.


There is a very famous saying in ML:

🗑️ "Garbage In, Garbage Out"
If your input features are bad → your output prediction will also be bad

So creating good features from text is very important. It directly decides how well your model works.

🧠 Real Example from Instructor

Let's say you are building a Sentiment Analysis system (positive/negative review detector).


Here are some features you can manually create from text:


FeatureWhat it means
Number of WordsHow many total words are in the review?
Number of Negative WordsCount of words like "bad", "worst", "hate"
Number of Positive WordsCount of words like "good", "great", "love"
Average Word LengthAverage number of letters per word

All of these are numeric features you create FROM the text.

🧠 Instructor's Key Insight
A weak algorithm with great features will beat a great algorithm with weak features.

This means: spend more time on your features than on your algorithm choice.

Why is Converting Text to Numbers Difficult?

🎯 Goal: Understand why text is harder to convert than images or audio
💡 Comparison

Let's compare three types of data and see how hard it is to convert each into numbers:


Data TypeConversion MethodDifficulty
🖼️ ImageEach pixel is already a number (0–255)🟢 Easy
🔊 Audio/SpeechSound wave → amplitude values → array of numbers🟡 Medium
📝 Text??? Not straightforward🔴 Hard
🧠 Why is Text Hard?
Image: A photo of digit "5" → just read the pixel values → done ✅

Audio: "Hello" spoken → record the sound wave values → done ✅

Text: "Hello, how are you?" → hmm... what exactly becomes the number? 🤔
There is no direct mapping. You have to think and design a way to represent meaning using numbers.
🖼️ Image Example (Instructor used this)
Handwritten digit "5" image: ┌────────────────────────────────┐ │ 0 0 0 255 255 200 0 0 0 │ ← Pixel rows │ 0 0 255 200 0 0 0 0 0 │ │ 0 200 255 0 0 0 0 0 0 │ └────────────────────────────────┘ → Each pixel = 1 number → the whole image = a big array of numbers → Easy! Already in numeric form.
Now try this with text: "The movie was amazing, I loved it!" → How do you turn "amazing" into a number? → Does it become 7? Or 42? Or [0,0,1,0,0,0,1]? → This is the challenge. No obvious rule exists.

The Core Idea: What Should the Numbers Represent?

🎯 Goal: Understand the ONE rule that guides all text-to-number conversion
💡 The Golden Rule

When you convert text to numbers, your numbers must preserve the meaning (semantic meaning) of the text.


🎯 Goal: The numbers should carry the "hidden meaning" of the text.


✅ If two sentences have similar meaning → their numbers should be similar

❌ If two sentences have different meaning → their numbers should be different

🧠 Mental Model — The Semantic Compass
Think of it like GPS coordinates:

Two cities that are close to each other have similar coordinates.
Two cities that are far apart have very different coordinates.

Similarly, two sentences that are close in meaning should have close numbers (vectors).
This is the core goal of text representation.
🖼️ Visual — Good vs Bad Representation
GOOD Representation: "I love this phone" → [0.9, 0.1, 0.8, 0.2] "This phone is amazing" → [0.85, 0.12, 0.78, 0.25] (Similar meaning → Similar numbers) ✅ BAD Representation: "I love this phone" → [0.1, 0.9, 0.3, 0.7] "This phone is amazing" → [0.8, 0.0, 0.9, 0.1] (Same meaning → Totally different numbers) ❌
🧠 Think Questions
❓ "Cat" and "Kitten" mean almost the same thing. Should their numeric representations be close or far apart?
❓ "Hot" and "Cold" mean opposite things. Should their representations be very similar or very different?
🗣️ Teach-Back Prompt
"Explain to a friend: Why can't we just randomly assign numbers to words? What problem would that cause?"
🌍 Real-Life Example
🌡️ Thermometer Analogy: A thermometer converts "hotness" into numbers. 37°C means one thing, 40°C means another. The numbers preserve the meaning — you can tell which is hotter just by looking at numbers. Good text representation should work the same way.

Key Terms You Must Know

🎯 Goal: Learn 4 important words used throughout NLP — they will appear everywhere
💡 Dataset Used: IMDB Movie Reviews

The instructor uses the IMDB Movie Reviews dataset to explain these terms.


It has 50,000 movie reviews. Each row has:

  • The review text (e.g., "This movie was amazing!")
  • The sentiment (positive or negative)
🖼️ All 4 Terms Explained
📚 Corpus
C

The entire collection of all text data. All 50,000 reviews put together = the Corpus. All words, all sentences, everything — including repeated words.

📖 Vocabulary
V / vocab

The set of all unique words in the Corpus. If "good" appears 500 times, it is counted only ONCE in the Vocabulary. Typically much smaller than Corpus.

📄 Document
D

Each individual review is one Document. If there are 50,000 reviews, there are 50,000 Documents.

🔤 Word / Token
W / T

Each individual word inside a Document. In "I love movies" — there are 3 tokens: "I", "love", "movies".

🖼️ Visual — Seeing All Terms Together
CORPUS = Everything combined ────────────────────────────────────────────── Document 1: "The movie was great, I loved it" Document 2: "Terrible film, worst experience ever" Document 3: "Great acting, loved the story" ... 50,000 documents total ────────────────────────────────────────────── VOCABULARY = Unique words only {the, movie, was, great, I, loved, it, terrible, film, worst, experience, ever, acting, story, ...} → Maybe 20,000–100,000 unique words from 50K reviews TOKENS from Document 1: "The" "movie" "was" "great" "I" "loved" "it" → 7 tokens / words in this document

⚠️ Common Mistakes

❌ Mistakes Beginners Make

  • Corpus ≠ Vocabulary. Corpus has ALL words (with repeats). Vocabulary has only UNIQUE words.
  • Thinking each sentence = corpus. No — the WHOLE dataset together = corpus.
  • Thinking vocabulary size = corpus size. Usually vocabulary is 10x–100x smaller.

💡 One-Hot Encoding — Quick Intro

This is the simplest technique. Each word in your vocabulary gets a position.


The word is represented as a vector of 0s and one 1.

Vocabulary: {I, love, tea, hate, coffee} → 5 words "love" → [0, 1, 0, 0, 0] (1 at position of "love") "tea" → [0, 0, 1, 0, 0] (1 at position of "tea") "coffee" → [0, 0, 0, 0, 1] (1 at position of "coffee") Every word → its own vector of 0s and 1s

⚠️ Problem with One-Hot Encoding

It does not capture any meaning or relationship between words.
"King" and "Queen" would have completely unrelated vectors, even though they are related concepts.

💡 Bag of Words — Quick Intro

Count how many times each vocabulary word appears in a document.

The order of words doesn't matter (imagine throwing words in a bag — that's why it's called "Bag of Words").

Vocabulary: {I, love, tea, hate, coffee} Document 1: "I love tea and I love coffee" Count: [2, 2, 1, 0, 1] I love tea hate coffee Document 2: "I hate coffee" Count: [1, 0, 0, 1, 1] I love tea hate coffee
💡 Custom Features — Quick Intro

Sometimes, your own knowledge of the problem helps you create better features.


Examples of custom features you can make from text:

  • Total word count in the review
  • Number of exclamation marks (!)
  • Number of capital letters
  • Number of negative words (bad, terrible, worst)
  • Average word length
  • Number of question marks
💡 When to use custom features?
Use them when you have domain knowledge. A doctor analyzing medical notes would know which words matter most. A lawyer analyzing legal documents would know which phrases are important.
💡 Word Embeddings — Preview (Next Video)

This is the most powerful technique. It uses Deep Learning to convert words into rich, meaning-preserving vectors.


Famous example: Word2Vec


"King" - "Man" + "Woman" = "Queen" (using math on vectors!)

This will be covered in the next video. Today we focus on the basics.

⚠️ Common Mistakes

❌ Top Beginner Mistakes

  • Thinking One-Hot Encoding captures word meaning — it does NOT
  • Using very rare words in vocabulary (makes the vector too large and sparse)
  • Forgetting to preprocess text (lowercase, remove punctuation) before feature extraction
  • Skipping stop words removal — words like "the", "is", "and" don't add meaning
