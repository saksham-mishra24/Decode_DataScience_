# 🤖 Logistic Regression vs Decision Tree

Professor Arjun drew two models on the board.

### Logistic Regression

Logistic regression draws **one straight line**.

```
----------- decision boundary ----------
```

Everything above → Pass
Everything below → Fail

Simple.

But sometimes the data is messy.

---

### Decision Tree

A decision tree does something very different.

Instead of **one line**, it creates **multiple splits**.

Example first question:

```
Study Hours > 3 ?
```

Graphically this creates a **vertical line**.

---

# 📏 First Split

```
Study Hours > 3
```

This means:

```
Left side  → Study Hours ≤ 3
Right side → Study Hours > 3
```

Geometrically this is:

```
A vertical line cutting the graph
```

Like slicing a cake.

---

# ✂ Second Split

Next Milo asks:

```
Attendance > 70% ?
```

That creates a **horizontal line**.

Now the graph looks like this:

```
+-----------+
|           |
|           |
|-----------|
|           |
+-----------+
```

We have **four regions** now.

Each region can have its own prediction.

---

# 🧩 Decision Trees Create Rectangles

Here is the big geometric idea:

> **Decision Trees split space into rectangles.**

Notice something interesting.

The boundaries are always:

Why?

Because each rule looks like:

```
Feature > Threshold
```

Example:

```
Study Hours > 3
Attendance > 70
Age > 25
```

Each rule cuts the graph **parallel to an axis**.

---

# 🍰 Cake Cutting Intuition

Professor Arjun gave Milo a cake analogy.

> 👨‍🏫 “Imagine your data is a cake.”

A decision tree **cuts the cake repeatedly**.

```
First cut
Second cut
Third cut
```

Eventually the cake becomes **small blocks**.

Each block contains mostly **one class**.

---

# 🧠 The Real Intuition

Decision Trees do this:

```
Step 1 → Divide the space
Step 2 → Divide again
Step 3 → Divide again
```

Until regions become **pure**.

Example:

```
Region 1 → mostly Pass
Region 2 → mostly Fail
Region 3 → mostly Pass
```

Each region becomes a **leaf node**.

---

# 🤖 Milo’s Thought Process

Now Milo thinks like this:

```
Which question splits the data best?
```

If a split separates **Pass and Fail nicely**, it’s a good split.

If a split mixes them badly, it’s a bad split.

But this raises a very important question.

---

# 🧩 The Big Mystery

Riya leaned forward.

> 👩 “But how does Milo know **which split is best**?”

For example:

```
Study Hours > 3 ?
Attendance > 60 ?
Age > 20 ?
```

Which one should come **first**?

This is where Decision Trees introduce a powerful idea:

```
Entropy
```

Entropy measures **how mixed or messy the data is**.

And the tree tries to **reduce the mess**.
